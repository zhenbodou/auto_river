Rust 智能驾驶开发：从小白到工程师

1.4 为什么在智能驾驶里用 Rust

这一节要给你弹药——不只是"Rust 很酷"，而是能在技术评审会上、面试里、和坚持 C++ 的老工程师辩论时站得住脚的论证。也要给你清醒——Rust 不是银弹，知道它的边界才是专业。

自动驾驶软件的三个"物理约束"

任何跑在车上的软件，都被三个残酷的约束框住：

  1. 实时性 (Real-time)：控制指令晚 100 ms 可能就是一场事故。系统必须在确定的时间预算内响应，不能有不可预测的卡顿。
  2. 安全攸关 (Safety-critical)：一个 bug 的代价可能是人命。行业有强制标准 ISO 26262（功能安全）和 ISO 21448（SOTIF，预期功能安全）。
  3. 资源受限 (Resource-constrained)：车载计算平台的算力、内存、功耗都有限，还要在 -40℃ 到 85℃ 的环境里稳定工作十年。

这三条决定了：带垃圾回收（GC）的语言（Java、Go）基本出局——GC 的"停顿"（stop-the-world）破坏实时性。于是几十年来主战场是 C/C++。它快、可控、贴近硬件。但它有个致命弱点……

C++ 的阿喀琉斯之踵：内存不安全

C/C++ 把内存管理完全交给程序员。一个疏忽就是：

  • 悬垂指针（use-after-free）：用了已经释放的内存。
  • 缓冲区越界（buffer overflow）：读写了不该碰的内存。
  • 数据竞争（data race）：多线程同时改一块内存，结果不可预测。

这些不是"小 bug"。微软和谷歌的统计一致表明：约 70% 的严重安全漏洞源于内存安全问题。在服务器上，这类 bug 导致崩溃或被黑；在车上，它可能导致感知模块在关键一帧返回垃圾数据，而系统毫不知情。

更麻烦的是，这些 bug 往往不可复现——它依赖于时序、内存布局，测试时好好的，量产车上偶发。对一个必须证明"足够安全"的系统，这是噩梦。

Rust 的核心承诺：编译期消灭这一整类问题

Rust 的设计目标就是：在不牺牲 C++ 性能的前提下，把上述内存和并发错误挡在编译期。它靠三样东西做到：

  1. 所有权 (Ownership)：每块内存有唯一的所有者，所有者离开作用域时内存自动释放——没有 GC，也没有手动 free。（第 2.2 节详讲）
  2. 借用检查 (Borrow Checker)：编译器静态地保证，任何时刻要么有多个只读引用，要么有一个可写引用，二者不可兼得。这从根上消灭了数据竞争。
  3. 无畏并发 (Fearless Concurrency)：因为借用规则同样管着线程间的数据共享，多线程数据竞争在编译期就被拒绝。

一句话总结这个价值主张：

Rust 让你写出 C++ 级别性能的代码，但编译器帮你证明了它没有内存错误和数据竞争。

对一个安全攸关、又高度并发（几十个模块同时跑）的自动驾驶系统，这个承诺的分量怎么强调都不过分。

一个具体的例子

看这段有 bug 的 C++（伪代码风格）：

std::vector<Obstacle>& get_obstacles();

void process() {
    Obstacle& first = get_obstacles()[0];  // 拿到第一个障碍物的引用
    update_obstacles();                     // 内部可能让 vector 扩容/重分配
    use(first);                             // 💥 first 可能已经悬垂！
}

update_obstacles() 若导致 vector 重新分配内存，first 就指向了已释放的旧内存。编译通过，运行时偶发崩溃或读到垃圾。

等价的 Rust 根本编译不过：

fn process(obstacles: &mut Vec<Obstacle>) {
    let first = &obstacles[0];       // 不可变借用
    obstacles.push(Obstacle::new()); // 可变借用 —— 编译器在此报错！
    use_obstacle(first);             // 借用检查器不允许 first 活到这里
}

编译器会明确告诉你："不能在存在不可变借用时进行可变借用"。你想犯这个错都犯不了。 这就是"编译期消灭一整类 bug"的具体含义。

不止安全：Rust 的其他实在好处

  • 零成本抽象：高级抽象（迭代器、泛型、trait）编译后和手写底层代码一样快，没有运行时开销。
  • 优秀的错误处理：用 Result 类型强制你处理错误路径（第 2.4 节），而不是像 C++ 异常那样容易被忽略——对必须优雅降级的车载系统极为重要。
  • 现代工具链：cargo 一个工具搞定构建、依赖、测试、文档。相比 C++ 的 CMake/Make/Conan 地狱，开发效率高一个数量级。
  • 一流的 FFI：能无缝调用 C 库（bindgen），意味着你能渐进式地在既有 C++ 系统里引入 Rust，而不是推倒重来——这正是行业目前的真实迁移路径。

行业里真实发生的采用

不要以为这是纸上谈兵：

  • ROS 2 社区有 Rust 客户端库 rclrs（第 8.2 节会说明能力与稳定性边界）。
  • Zenoh——被 ROS 2 选为新一代默认通信中间件（rmw_zenoh）——本身就是 Rust 写的（第 8.3 节）。
  • AWS 开源了自动驾驶数据处理工具链，多处用 Rust。
  • Volvo、以及多家自动驾驶和 Tier 1 公司已在中间件、嵌入式控制器、工具链里引入 Rust。
  • 你手边的 inf/ 推理 SDK，本身就是把一套 Python 数据处理流水线移植成 Rust的真实工程——这类"把关键路径从脚本语言换成 Rust 以获得性能和可靠性"的迁移，正在大量发生。

清醒剂：Rust 现在的边界

专业意味着也知道 Rust 不擅长什么、以及现实的阻力：

  • 生态仍在成熟：C++ 有几十年积累的自动驾驶库（PCL 点云库、OpenCV、Eigen 的深度集成、各厂商 SDK）。Rust 的对应生态更年轻，有时你得自己包一层 C++ 库。
  • 学习曲线陡：借用检查器一开始会让你"和编译器搏斗"。这是前期成本——熬过去之后，它变成帮你的朋友。
  • 算法研究仍是 Python 的天下：训练模型、快速实验、数据分析，PyTorch/NumPy 生态无可替代。Rust 主要在部署和工程化环节发力。
  • 团队现实：绝大多数在职团队的存量代码是 C++。你更可能是在一个 C++ 为主的系统里，负责用 Rust 写新的中间件、工具或某个模块。

所以务实的定位是：Rust 是你的差异化优势和主攻方向，但你要能读 C++、能写 Python 做数据处理。本书教 Rust，但会在关键处对照三语言，让你在真实团队里如鱼得水。

小结

  • 车载软件被实时性、安全攸关、资源受限三条物理约束框死，GC 语言出局，主战场是 C/C++。
  • C++ 的内存不安全是安全攸关系统的心头大患（~70% 严重漏洞的根源），且这类 bug 常常不可复现。
  • Rust 用所有权 + 借用检查在编译期消灭这一整类问题，同时保持 C++ 级性能——这是它在智驾领域的核心价值。
  • 行业采用（rclrs、Zenoh、多家公司）正在真实发生，你手边的 inf/ 就是一例。
  • 但要清醒：生态更年轻、学习曲线陡、研究仍属 Python。把 Rust 当差异化主攻，同时能读 C++、会用 Python。
