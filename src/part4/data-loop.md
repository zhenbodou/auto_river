# 4.6 感知数据闭环与量产评测

模型离线 mAP 提升不等于车辆更安全。量产感知的核心能力，是把路测失败稳定地变成数据、实验、回归集和发布证据。

## 闭环的七个状态

采集 → 触发/挖掘 → 去重与隐私处理 → 标注与质检 → 训练 → 分桶评测 → 仿真/回放与上车灰度。每一步都要有可追溯 ID；否则无法回答“这个模型见过测试集吗”“这个事故片段在哪次发布被覆盖”。

## 先定义事件，再采数据

盲目上传全量原始数据成本巨大且分布失衡。触发器可来自：规划急刹、接管、模型低置信度、多传感器分歧、规则违反、分布外特征和新颖度聚类。触发窗口要保留事件前后上下文和同步元数据。

## 数据集契约与防泄漏

数据 manifest 至少记录场景 ID、传感器/标定版本、地点/时间、天气、标签版本、许可与隐私状态、split。划分训练/验证/测试时按“行程/场景”分组，不能随机拆相邻帧，否则同一段道路会泄漏到测试集。

## 指标要分桶、带置信区间

总体 mAP 会淹没小目标、夜间、遮挡和雨雾退化。至少按类别、距离、尺寸、遮挡、天气、道路类型、传感器健康状态分桶，并同时报告：

- 安全相关召回和误检率；
- 定位/速度误差分位数与校准误差；
- 轨迹连续性、ID switch、时延与资源占用；
- 相对基线的变化及 bootstrap 置信区间。

模型输出 0.9 置信度的样本应大约 90% 正确。可用 reliability diagram、ECE/Brier score 检查校准；规划使用概率时，错误的“自信”比稍低的准确率更危险。

## 从离线指标到系统指标

建立三层门禁：

1. **模型层**：固定 golden set，数值/精度/性能回归。
2. **模块层**：日志回放，检查消息契约、跟踪连续性和 deadline。
3. **闭环层**：场景仿真，检查碰撞、TTC、舒适性、交通规则与 MRM。

任何精度收益都不能用不可接受的 p99 时延、内存或下游抖动换取。发布评审看 Pareto，而不是单指标冠军。

## 长尾、主动学习与 OOD

主动学习优先挑选“有信息量且覆盖不足”的片段，而不只是最低置信度。OOD 分数只能作为风险信号，不能保证识别所有未知；将其与传感器一致性、规则监控、几何 freespace 和保守规划共同使用。

## 实验与模型治理

每个候选模型应可从以下内容复现：代码 commit、训练配置、数据 manifest、随机种子、基础模型、导出/量化参数、运行时版本、目标硬件基准、已知限制。模型文件使用内容哈希和签名；部署包与评测报告绑定。

## 本章验收

为一个公开或合成检测数据集设计 manifest；人为制造“夜间小行人”退化，证明总体指标如何掩盖它；实现分桶报告和 bootstrap 置信区间；写一页发布决策，说明精度、p99 时延、内存和安全回放为何允许或拒绝上线。

## 小结

- 数据闭环是可追溯的生产系统，不是“多收数据再训练”。
- 量产评测必须分桶、带不确定性，并从模型贯通到闭环安全指标。
- 模型、数据、标定、运行时和发布证据必须绑定版本。
