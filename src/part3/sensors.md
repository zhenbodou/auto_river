# 3.1 传感器全家福：相机、激光雷达、毫米波、IMU、GNSS

上一部分你学会了 Rust 的所有权、并发和 crate 生态。从这一章开始，我们让 Rust 去干正事——处理真实的传感器数据。但在写第一行数据处理代码之前，你得先认识**数据是从哪来的**。

这章解决一个问题：**自动驾驶车上到底有哪些传感器，每一个"看"世界的方式有什么本质不同，各自在什么时候会骗你**。这不是硬件手册式的参数罗列。作为软件工程师，你不需要会焊电路，但你**必须**在脑子里对每种传感器建立一个"物理直觉"——它测的是什么物理量、精度受什么支配、什么天气/场景下会失效。因为当感知模块半夜在测试车上抽风时，能救你的往往不是更深的网络，而是一句"这天在下雨，激光雷达点云被雨滴打穿了"。

我们逐个过一遍，每种传感器都回答四个问题：**测什么、优缺点、什么时候失效、数据长什么样**。最后给一张对比表，并回答那个核心问题：既然每种都有短板，**为什么非要用一堆传感器凑在一起（多传感器融合）**。

## 一个统一的视角：主动 vs. 被动

先给你一把分类的尺子，比死记硬背强。

- **被动传感器（passive）**：只接收环境里已有的能量，自己不发射。**相机**接收光子，**IMU** 感受惯性力，**GNSS** 接收卫星信号。它们省电、不互相干扰，但**看天吃饭**——没光的相机就是瞎子。
- **主动传感器（active）**：自己发射能量（激光、无线电波、声波），再接收回波，靠"发射—反射—接收"的时间或频率变化来测量。**激光雷达、毫米波雷达、超声波**都是主动的。它们不怕黑，能直接测距离和速度，但功率、成本更高，且多辆车的主动传感器可能**互相干扰**。

记住这把尺子。后面每讲一个，你就往这两类里归。

## 相机（Camera）

### 测什么

相机是**被动**光学传感器，本质是把三维世界投影到二维像素平面上，记录每个像素的颜色（RGB）或亮度。它测的是**方向和纹理**，**不直接测距离**——这是它最要命的短板。一个 `1920×1080` 的相机每帧约 6 MB，30 Hz 就是每秒 180 MB 的洪流。

相机是唯一能读**语义**的传感器：红绿灯是红是绿、路牌写着"限速 40"、地上的车道线是虚是实——这些信息只有相机（结合神经网络）能给。这也是为什么就算你装了最贵的激光雷达，也甩不掉相机。

### 针孔模型与内参

理解相机，从**针孔相机模型（pinhole camera model）**开始。想象一个针孔，三维世界的点 $P = (X, Y, Z)$ 在相机坐标系里，通过针孔投影到成像平面上的像素 $(u, v)$。这个投影由**内参矩阵（intrinsic matrix）** $K$ 描述：

$$
\begin{bmatrix} u \\ v \\ 1 \end{bmatrix}
= \frac{1}{Z} K \begin{bmatrix} X \\ Y \\ Z \end{bmatrix},
\qquad
K = \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}
$$

- $f_x, f_y$ 是**焦距**（以像素为单位），决定"放大倍数"。
- $c_x, c_y$ 是**主点**（principal point），通常在图像中心附近。
- 那个 $\frac{1}{Z}$ 就是"近大远小"的数学来源——除以深度 $Z$。

关键洞察就藏在这个 $\frac{1}{Z}$ 里：**投影丢掉了深度**。同一个像素 $(u,v)$，可能对应近处的小物体，也可能对应远处的大物体。单目相机想恢复距离，只能靠先验（假设地面平坦、假设车宽 1.8 米）或运动视差，都不可靠。这就是为什么纯视觉方案要么上双目/多目，要么用神经网络"猜"深度。

### 外参：相机装在哪

内参描述相机自己的成像几何，**外参（extrinsic）**描述相机**装在车上的哪个位置、朝哪个方向**——它是一个从"车体坐标系"到"相机坐标系"的刚体变换（下一章 3.2 的主角）。没有准确外参，你在图像里检测到的行人就没法映射回车周围的物理空间。**标定（calibration）**就是测量内参和外参的过程，一次没标好，后面全错。

> **真实项目里**：外参会随着车辆颠簸、温度变化、甚至某次维修拆装而漂移。量产系统会做**在线标定（online calibration）**，用道路上的车道线、灯杆等结构持续微调外参。一个"莫名其妙"的感知偏差，查到最后常常是外参漂了。

### 畸变

真实镜头不是理想针孔，光线在边缘会弯，直线拍出来变弯——这就是**畸变（distortion）**。最常见的是**径向畸变（radial distortion）**（桶形/枕形）和**切向畸变（tangential distortion）**。用一组畸变系数 $(k_1, k_2, k_3, p_1, p_2)$ 建模，处理图像前通常先**去畸变（undistortion）**把它掰直。广角/鱼眼镜头畸变极大，模型也更复杂。

### 优缺点与失效场景

- **优点**：分辨率高、有颜色和语义、便宜（几十到几百块）、功耗低。
- **缺点**：不直接测距、受光照支配。
- **失效场景**：夜间无路灯、进出隧道的瞬间**过曝/欠曝**、正对太阳的眩光、大雨大雾、镜头被泥水糊住。相机是"晴天白盒、暗夜瞎子"。

### 数据形态

```rust,ignore
/// 一帧原始图像（详细的数据结构设计见 3.4 节）
pub struct ImageFrame {

    pub height: u32,

    pub timestamp_ns: u64,       // 曝光中点的时间戳，别用"收到帧的时刻"
}
```

## 激光雷达（LiDAR）

### 测什么

**LiDAR = Light Detection and Ranging。主动**传感器：发射激光脉冲，测量从发射到收到反射回波的**飞行时间（Time of Flight, ToF）**，用光速换算出距离：

$$
d = \frac{c \cdot \Delta t}{2}
$$

（除以 2 是因为光走了个来回。）光速 $c \approx 3\times10^8$ m/s，要测出厘米级距离，计时精度得到亚纳秒级——这就是为什么好激光雷达贵。

它一秒钟向四面八方打出几十上百万个脉冲，每个回波给你一个三维点 $(x, y, z)$，外加一个**强度（intensity）**。成千上万个点堆在一起，就是**点云（point cloud）**——世界的三维几何直接摆在你面前，不用像相机那样去"猜"深度。这是激光雷达的杀手锏。

### 强度（intensity）是什么

除了 xyz，每个点还带一个**反射强度**，反映目标表面的反射率。车道线的白漆、交通标牌的反光膜强度很高，沥青路面强度低——所以点云强度能用来**检测车道线**，甚至在没有相机时提取部分语义。别浪费这一维。

### 机械式 vs. 固态

- **机械式旋转（mechanical spinning）**：一圈激光发射器绕轴 360° 旋转，`10~20 Hz` 转一圈。视场全、技术成熟，但有旋转部件、体积大、贵、寿命受机械磨损限制。经典的 Velodyne 就是这类，顶在车顶那个"警灯"。
- **固态/半固态（solid-state）**：用 MEMS 微振镜、光学相控阵（OPA）或 Flash 方式扫描，没有大的旋转机构。更便宜、更小、更耐振动、易过车规，但通常视场角有限，需要多个拼接。这是量产降本的方向。

一个重要的工程细节：机械式激光雷达转一圈需要时间（比如 100 ms），所以**一帧点云里不同方位的点是在不同时刻采集的**。车在动、目标也在动，同一帧内就有了"运动畸变（motion distortion）"。严谨的做法要用每个点的**逐点时间戳**加上位姿做**去畸变（deskew）**。初学者最容易忽略这一点。

> **面试题**：一圈机械式激光雷达点云，能不能当成"同一时刻的快照"来用？
> **答**：不能。10 Hz 转一圈是 100 ms，车以 10 m/s 跑，这一圈的头和尾之间车已经移动了 1 米。高精度感知/建图必须用逐点时间戳配合自车运动做去畸变，否则近处的墙会被"抹歪"。

### 优缺点与失效场景

- **优点**：直接给精确三维几何、白天黑夜一样、测距精度厘米级。
- **缺点**：贵（虽在快速降本）、点云稀疏（远处物体只有几个点）、数据量大、有运动畸变问题。
- **失效场景**：**雨雪雾**——激光被水汽/雨滴散射衰减，还会在雨滴上产生虚假回波（"雪花点"）；玻璃、镜面、纯黑物体几乎不反射，成"空洞"；尾气、扬尘也会产生噪点。

### 数据形态

```rust
pub struct PointXYZI {
    pub x: f32,
    pub y: f32,
    pub z: f32,
    pub intensity: f32,
}
// 一帧点云就是 Vec<PointXYZI>，通常 5万~30万点。
// 内存布局（SoA vs AoS）对处理性能影响巨大，见 3.4 节。
```

## 毫米波雷达（Radar）

### 测什么

**Radar = Radio Detection and Ranging。主动**传感器，发射毫米波段（常见 77 GHz）的无线电波。它一次给你三样东西：**距离、方位角、以及最珍贵的——径向速度**。

径向速度来自**多普勒效应（Doppler effect）**：目标朝你运动，反射回来的波频率会升高；远离你，频率降低。频率的偏移量 $f_d$ 与径向速度 $v_r$ 成正比：

$$
f_d = \frac{2 v_r}{\lambda}
$$

其中 $\lambda$ 是波长。注意这个 **2** 又是来回的意思。关键点：**毫米波雷达直接、物理地测出速度**，不用像激光/相机那样靠"两帧位置相减"去估计。这一维速度信息在跟踪快速运动目标（比如高速上突然切入的车）时是黄金。

### 优缺点与失效场景

- **优点**：**几乎不受天气影响**（雨雾雪照穿）、直接测速、探测距离远（200 米以上）、便宜、成熟到几乎每辆量产车都有（自适应巡航靠它）。
- **缺点**：**角分辨率差**——它能告诉你"前方 50 米有个东西以 20 m/s 靠近"，但那东西是一辆车还是并排两辆车，它常常分不清；对**静止物体**处理头疼（为了滤掉护栏、井盖、路牌等静止杂波，早期雷达算法干脆忽略静止目标，于是就有了"雷达对静止的消防车视而不见"这类著名事故）。
- **失效场景**：金属栏杆、隧道壁产生的**多径反射（multipath）**造成鬼影；密集杂波环境（城市）里虚警多。

### 数据形态

雷达输出通常不是点云，而是一组**目标点（detections / tracks）**：

```rust
pub struct RadarDetection {
    pub range: f32,          // 距离 (米)
    pub azimuth: f32,        // 方位角 (弧度)
    pub radial_velocity: f32,// 径向速度 (米/秒)，来自多普勒
    pub rcs: f32,            // 雷达散射截面，反映目标"大小/材质"
}
```

新一代**4D 成像毫米波雷达（4D imaging radar）**增加了俯仰维和更高分辨率，开始能输出类点云的稠密数据，正在部分场景里蚕食低线束激光雷达的地盘。

## 超声波（Ultrasonic）

**主动**声波传感器，靠声波 ToF 测距。**测什么**：近距离（几厘米到 5 米）障碍物。**优点**：极便宜、近距离准。**缺点**：距离短、方向模糊、刷新慢、受风和温度影响。**用在哪**：泊车（那个"滴滴滴"倒车雷达就是它）、近距离盲区。它上不了高速决策的台面，但泊车场景离不了。数据形态最简单：几个通道各自一个距离值。

## IMU（惯性测量单元）

### 测什么

**IMU = Inertial Measurement Unit**，被动传感器，通常包含：

- **加速度计（accelerometer）**：测三轴**比力（specific force）**，即加速度（含重力）。静止时它能测到指向天空的 1g 重力——这可以用来估计车的俯仰/横滚姿态。
- **陀螺仪（gyroscope）**：测三轴**角速度**。

IMU 的频率极高（`100~1000 Hz`），是所有传感器里最快的。它不依赖任何外部信号，隧道里、地下车库里照样工作——这是它在定位里不可替代的原因。

### 噪声与零偏：为什么不能只靠 IMU

IMU 的读数 = 真值 + **零偏（bias）** + **噪声（noise）**。对角速度积分得到角度、对加速度**积分两次**得到位置，误差会随时间**累积漂移（drift）**。零偏哪怕只有 $0.01°/s$，积分一分钟角度就偏了 $0.6°$，再投影到几十米外就是米级误差。加速度计的零偏经两次积分，误差随时间**平方**增长——几秒钟就发散。

所以 IMU 从来不单独用。它的角色是"短时间内极其可靠的高频推算"，用来在两次 GNSS/激光定位之间"填空"，长期漂移则靠其他传感器来"拉回"。这正是第五部分**组合导航（GNSS/IMU fusion）**和卡尔曼滤波要解决的核心问题。

> **中高级视角**：IMU 有消费级、工业级、导航级之分，差在零偏稳定性和随机游走，价格能差几个数量级。选型时问的第一个问题永远是"零偏稳定性（bias stability）多少"，而不是"多少 Hz"。

### 数据形态

```rust
pub struct ImuSample {
    pub angular_velocity: [f64; 3],     // 陀螺仪, rad/s
    pub linear_acceleration: [f64; 3],  // 加速度计, m/s^2 (含重力)
    pub timestamp_ns: u64,
}
```

## GNSS（全球卫星导航系统）

### 测什么

**GNSS = Global Navigation Satellite System**，是 GPS（美）、北斗（中）、GLONASS（俄）、Galileo（欧）的统称。被动传感器，接收多颗卫星信号，靠信号飞行时间做**三角定位**，输出**大地坐标**——经度、纬度、高程（WGS84 坐标系，见下一章）。

普通民用 GNSS 精度是**米级**（3~10 米），且更新慢（`1~10 Hz`）。对高速行驶的车来说，"我在这条车道还是隔壁车道"这种问题，米级精度根本回答不了。

### RTK：厘米级的魔法

**RTK（Real-Time Kinematic，实时动态载波相位差分）**通过一个位置已知的**地面基站**，实时播发卫星信号的误差修正量，让移动的车辆消除大气延迟等公共误差，把精度从米级提到**厘米级（1~2 cm）**。高精定位系统几乎都依赖 RTK 或类似的差分/PPP 技术。代价是要有基站网络或订阅差分服务，且信号中断后需要重新收敛。

### 优缺点与失效场景

- **优点**：提供**绝对**位置（全球唯一坐标），不漂移（不像 IMU），RTK 下厘米级。
- **缺点**：更新慢、有延迟、需要"看得见天空"。
- **失效场景**：**隧道、地下车库、城市峡谷（高楼间）**——信号被遮挡或产生**多径**，位置会突然跳几米甚至十几米。这也是为什么定位绝不能只信 GNSS，必须和 IMU、激光/视觉里程计融合。

### 数据形态

```rust,ignore
pub struct GnssFix {
    pub latitude: f64,     // 纬度 (度)
    pub longitude: f64,    // 经度 (度)
    pub altitude: f64,     // 高程 (米)
    pub fix_type: FixType, // NoFix / Single / DGPS / RtkFloat / RtkFixed
    pub hdop: f32,         // 水平精度因子，越小越好
    pub timestamp_ns: u64,
}
```

看到 `fix_type` 了吗？工程上你**必须**检查它。`RtkFixed` 才是厘米级；掉到 `Single` 就是米级——盲目相信一个正在 `Single` 状态下的 GNSS，定位就飞了。

## 轮速里程计（Wheel Odometry）

最朴素的传感器：数**车轮转了多少圈**。乘以轮子周长就是行驶距离，配合转向角能推算车的运动（**航迹推算，dead reckoning**）。**优点**：便宜、高频、隧道里也工作。**缺点**：**打滑（slip）**时彻底失真——冰雪路面车轮空转，里程计以为你开了 10 米实际没动；轮胎磨损/气压变化让周长标定失准，长距离累积误差。它和 IMU 一样，是"短时可靠、长期漂移"的推算类传感器，融合里当"运动约束"用。

## 为什么要多传感器融合

看完这张表，答案应该已经在你脑子里成型了：**没有任何单一传感器是全能的，但它们的短板恰好可以互补。**

- 相机有语义、没深度；激光雷达有深度、没语义——**相机 + 激光雷达**，既知道"那是什么"又知道"在哪、多远"。
- 相机/激光雷达怕雨雾；毫米波雷达雨雾照穿——**加一个雷达**，恶劣天气下不至于全瞎。
- GNSS 有绝对位置但隧道失效、更新慢；IMU 高频不漂但长期发散——**GNSS + IMU + 轮速**融合，隧道里靠惯性推算撑住，出隧道靠 GNSS 拉回。
- 激光雷达测速靠两帧相减、有延迟；毫米波直接给径向速度——融合后跟踪快速目标又快又准。

这就是**多传感器融合（multi-sensor fusion）**的根本逻辑：用信息的**冗余**换**鲁棒性**，用能力的**互补**换**完备性**。一个传感器骗你时，别的传感器能拆穿它。功能安全（ISO 26262）里对关键功能要求"不能有单点失效"，多传感器就是感知层实现这一点的手段。

但融合不是"把数据堆一起"那么简单。要融合，你必须先解决两个前提问题：

1. **不同传感器的数据在不同坐标系里**——相机在相机系、激光在激光系、GNSS 在大地系。得先统一到同一个坐标系才能比较。这是 **3.2 坐标系与刚体变换**的主题。
2. **不同传感器的数据在不同时刻产生**——频率不同、时间戳不同。得先对齐到同一时刻才能融合。这是 **3.3 时间戳与同步**的主题。

坐标对齐 + 时间对齐，是融合的两块基石。缺一块，融合就是在制造垃圾。

## 小结

- 用**主动/被动**这把尺子给传感器归类：主动的（激光、毫米波、超声波）不怕黑能测距，被动的（相机、IMU、GNSS）省电但看天/看信号吃饭。
- **相机**给语义不给深度、**激光雷达**给精确三维几何但怕雨雾且有运动畸变、**毫米波**靠多普勒直接测速且不惧天气但角分辨率差、**IMU/轮速**高频可靠但长期漂移、**GNSS(RTK)** 给厘米级绝对位置但隧道失效。
- 每种传感器都有明确的**失效场景**——记住它们，比记参数更重要。工程上永远要检查数据的质量标志（如 GNSS 的 `fix_type`）。
- **多传感器融合**的本质是用冗余换鲁棒、用互补换完备，让单一传感器的谎言被拆穿。
- 融合的两块基石是**坐标对齐**和**时间对齐**，正好是接下来两章的主题。
