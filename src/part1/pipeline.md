# 1.3 感知—定位—预测—规划—控制 五大模块

上一节给了框图。这一节我们**跟着一帧数据走一遍**，带上具体的数据结构、坐标、和数量级。读完你脑子里应该能"编译"出这套流水线的伪代码。

## 场景设定

你的车正以 **10 m/s**（36 km/h）在城市道路直行。前方 30 米，一个行人站在路边，似乎要横穿。我们看这一瞬间，系统内部发生了什么。整个决策必须在**一个控制周期**（比如 20 ms，即 50 Hz）内完成一轮。

## 第 0 步：传感器产出原始数据

在某个时刻 `t`，各传感器几乎同时产出：

- **相机**：一帧 `1920×1080` 的 RGB 图像，约 6 MB。
- **激光雷达**：一圈点云，约 12 万个点，每个点 `(x, y, z, intensity)`，约 2 MB。
- **毫米波雷达**：几十个"目标"，每个带距离、方位、径向速度。
- **IMU**：3 轴加速度 + 3 轴角速度，`200 Hz` 高频。
- **GNSS**：经纬度 + 高程，`10 Hz`，米级精度。
- **轮速**：四个轮子的转速。

注意：它们的**频率不同、时间戳不同**。第一件工程上要命的事就是**时间同步**（第 3.3 节详述）。现在先假设我们已经把它们对齐到同一时刻 `t`。

## 第 1 步：感知——世界变成一张"障碍物清单"

感知模块拿到图像和点云，跑一堆神经网络和几何算法，最后吐出一份结构化清单。用 Rust 表达大概是：

```rust
/// 一个被感知到的障碍物（本书后续会反复用到这个结构）
#[derive(Debug, Clone)]
pub struct Obstacle {
    pub id: u32,                 // 跟踪 ID，跨帧保持不变
    pub class: ObstacleClass,    // 车/人/自行车/未知
    pub position: [f64; 3],      // 在“自车坐标系”下的 x,y,z (米)
    pub velocity: [f64; 3],      // 速度矢量 (米/秒)
    pub size: [f64; 3],          // 长宽高 (米)
    pub heading: f64,            // 朝向角 (弧度)
    pub confidence: f32,         // 置信度 0~1
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum ObstacleClass {
    Vehicle,
    Pedestrian,
    Cyclist,
    Unknown,
}
```

对我们的行人，感知输出可能是：

```text
Obstacle {
    id: 42,
    class: Pedestrian,
    position: [30.0, -1.5, 0.0],   // 前方 30m，右侧 1.5m
    velocity: [0.0, 0.3, 0.0],     // 正以 0.3 m/s 向左（朝车道）移动！
    size: [0.5, 0.5, 1.7],
    heading: 1.57,                 // 朝向 +y（横穿方向）
    confidence: 0.92,
}
```

**关键信息已经在数据里了**：这个行人有一个指向车道的横向速度 `velocity.y = 0.3`。感知只负责"看到"，不负责"预判"——那是下一步的事。

> **中高级视角**：感知输出的每个字段都带**不确定性**。生产系统里 `position` 往往不是一个点，而是一个带协方差的高斯分布；`class` 不是一个枚举，而是一个概率分布。本书 4.5 节讲跟踪与融合时会把这些不确定性显式建模——这正是初级和高级感知工程师的分野。

## 第 2 步：定位——我在地图的哪里

与感知并行，定位模块融合 GNSS、IMU、轮速和地图特征，输出自车位姿：

```rust
#[derive(Debug, Clone, Copy)]
pub struct Pose {
    pub position: [f64; 3],   // 在“地图坐标系”下的位置
    pub yaw: f64,             // 航向角
    pub pitch: f64,
    pub roll: f64,
}
```

有了位姿，系统就能把"自车坐标系"下的障碍物，换算到"地图坐标系"，从而结合高精地图知道：这个行人正站在**人行道边缘**、前方 50 米有个**红绿灯**、当前车道**限速 40**。**地图 + 定位 = 给一切决策提供上下文。**

## 第 3 步：预测——他接下来要干什么

预测模块拿到"横向速度 0.3 m/s 朝车道的行人"+"他站在人行横道附近"这两个信息，推断：

```text
行人 #42 的未来 3 秒轨迹预测：
  轨迹 A（横穿马路）：概率 0.7
  轨迹 B（在原地等待）：概率 0.3
```

预测的输出通常是**多模态**的（多条轨迹 + 概率），因为人的意图本质不可知。规划模块必须对**所有**足够可能的模态都保持安全。

> **面试题**：为什么预测输出要是多条轨迹而不是一条最可能的？
> **答**：因为对小概率但高风险的模态（行人真的冲出来）不做准备，就是拿命赌。规划要的是"对所有可能都安全"，不是"对最可能的安全"。

## 第 4 步：规划——所以我该怎么走

规划模块综合：自车位姿、行人的多模态预测、地图（车道、限速）、导航目标（要直行），求解出一条未来几秒的轨迹。它内部通常分两层：

- **行为决策**：先做离散决策——"减速让行"还是"保持速度通过"？基于风险和交规，这里选**减速让行**。
- **轨迹生成**：在决策约束下，生成一条平滑、舒适、动力学可行的轨迹。

输出是一串带时间戳的轨迹点：

```rust
#[derive(Debug, Clone, Copy)]
pub struct TrajectoryPoint {
    pub t: f64,          // 相对当前的时间 (秒)
    pub x: f64,          // 地图坐标
    pub y: f64,
    pub v: f64,          // 该点的期望速度 (米/秒)
    pub heading: f64,    // 该点的期望朝向
}

pub type Trajectory = Vec<TrajectoryPoint>;
```

对我们的场景，规划会输出一条"从 10 m/s 平滑减速到 3 m/s、必要时停车"的轨迹。

## 第 5 步：控制——精确地执行

控制模块拿到这条轨迹和当前车辆真实状态，算出**这一瞬间**方向盘、油门、刹车该给多少，让车**跟上**轨迹。

- 纵向（速度）：轨迹要减速，控制器输出**刹车 20%**。
- 横向（转向）：轨迹基本直行，控制器输出**方向盘 0.5°** 微调以保持车道居中。

```rust
#[derive(Debug, Clone, Copy)]
pub struct ControlCommand {
    pub steering_angle: f64,   // 方向盘转角 (弧度)
    pub throttle: f64,         // 油门 0~1
    pub brake: f64,            // 刹车 0~1
}
```

这个指令通过**线控（by-wire）**接口发给底盘，电机和液压系统执行，车真的开始减速。车动了，物理世界变了，下一帧传感器数据又进来了——**闭环**。

## 把它串起来：一段"伪流水线"

```rust,ignore
// 极度简化的主循环，只为建立整体感觉——真实系统是多进程/多线程并发的
fn autonomy_tick(sensors: &SensorFrame, map: &HdMap) -> ControlCommand {
    let obstacles: Vec<Obstacle> = perceive(sensors);
    let ego_pose: Pose = localize(sensors, map);
    let predictions = predict(&obstacles, map, ego_pose);
    let trajectory: Trajectory = plan(ego_pose, &predictions, map);
    let command: ControlCommand = control(&trajectory, sensors.vehicle_state);
    command
}
```

**但请记住**：真实系统绝不是这样一个函数顺序调用的。每个模块是**独立的进程/节点**，以**各自的频率**运行，通过**中间件**异步通信。感知可能 10 Hz，控制可能 100 Hz，它们并发运行、互相订阅消息。把上面的顺序调用当成理解模型，把"并发的、消息驱动的、各跑各频率的节点图"当成工程现实。第八部分我们会真的用 Rust 把它搭出来。

## 小结

- 我们跟着一帧数据走完了**感知→定位→预测→规划→控制**，每一步都有具体的数据结构。
- 感知给"清单"，定位给"我在哪"，预测给"他要干嘛（多模态）"，规划给"我怎么走（决策+轨迹）"，控制给"这一刻踩多少"。
- **不确定性**（感知的协方差、预测的多模态）贯穿始终，是中高级工程的核心。
- 现实是**并发的节点图**，不是顺序函数调用——这是第八部分的主题。
