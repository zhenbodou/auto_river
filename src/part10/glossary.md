# 10.3 常见术语表

这是一本**查阅用**的章节，不用从头读。当你在源码、论文或本书别处撞见一个缩写卡住时，翻到这里。术语按主题分组，每条给**中英文对照**加**一句话解释**——解释力求"让你当场接得上话"，想深挖就去对应章节。

> 用法提示：术语后面标了 `→ x.y` 的，是本书讲得最细的那一节。

## 分级、安全与运行域

- **L0–L5（自动驾驶分级 Levels of Automation）**：SAE 定义的六级，L0 全人工到 L5 全自动、任意场景无需人接管。当下量产主力是 L2+，Robotaxi 冲 L4。→ 1.1
- **ODD（运行设计域 Operational Design Domain）**：一套自动驾驶系统被设计为能安全工作的条件边界（道路类型、天气、速度、地理围栏）。ODD 越窄越好落地。→ 1.1
- **DDT（动态驾驶任务 Dynamic Driving Task）**：实时执行驾驶所需的全部操作与决策，分级的本质就是"DDT 由谁负责"。→ 1.1
- **ODD 退出 / MRC（最小风险状态 Minimal Risk Condition）**：系统超出能力或 ODD 时，自动进入的安全兜底状态（如靠边停车）。→ 9.3
- **MRM（最小风险策略 Minimal Risk Maneuver）**：把车带入 MRC 的那套动作。
- **ASIL（汽车安全完整性等级 Automotive Safety Integrity Level）**：ISO 26262 里对功能安全要求的分级（A 最低到 D 最高），决定开发流程的严苛程度。→ 9.3
- **ISO 26262**：道路车辆功能安全国际标准，管"系统故障导致的风险"。→ 9.3
- **SOTIF / ISO 21448（预期功能安全 Safety Of The Intended Functionality）**：管"没有故障、但功能本身局限导致的风险"（如感知在逆光下漏检）。与 26262 互补。→ 9.3
- **功能安全（Functional Safety）**：确保系统失效时仍处于可接受的安全状态的工程学科。→ 9.3
- **安全论证（Safety Case）**：用主张、论据和版本一致的证据说明系统风险已得到充分控制。→ 9.5
- **ISO/SAE 21434**：道路车辆网络安全工程标准，覆盖从概念、开发到运营维护的生命周期。→ 9.4

## 传感器与硬件

- **LiDAR（激光雷达 Light Detection and Ranging）**：发射激光测距，产出三维点云，精度高、直接给几何，贵且怕雨雾。→ 3.1
- **点云（Point Cloud）**：LiDAR 输出的一组带坐标（有时含强度）的三维点集合。→ 4.4
- **毫米波雷达（Radar）**：发射毫米波，直接测径向速度和距离，全天候但角分辨率低。→ 3.1
- **相机（Camera）**：产出稠密图像，语义信息最丰富，但不直接给距离、怕光照。→ 3.1
- **IMU（惯性测量单元 Inertial Measurement Unit）**：测三轴加速度和角速度，高频，但积分会漂移。→ 3.1
- **GNSS（全球导航卫星系统 Global Navigation Satellite System）**：GPS/北斗等的统称，给绝对位置，米级、城市峡谷里易失效。→ 3.1
- **RTK（实时动态定位 Real-Time Kinematic）**：用地面基站差分校正 GNSS，把精度提到厘米级。→ 5.2
- **组合导航（GNSS/IMU Integration）**：融合 GNSS 的绝对位置和 IMU 的高频相对运动，取长补短。→ 5.2
- **线控（By-wire / Drive-by-wire）**：用电信号而非机械连接控制转向/油门/刹车，是自动驾驶执行的接口。→ 1.3

## 感知

- **目标检测（Object Detection）**：在图像或点云里框出物体并分类，感知的核心任务之一。→ 4.1
- **语义分割（Semantic Segmentation）**：给每个像素/点打类别标签（路面、车、人……）。→ 4.1
- **实例分割（Instance Segmentation）**：分割的同时区分同类的不同个体。→ 4.1
- **跟踪（Tracking / MOT，多目标跟踪 Multi-Object Tracking）**：跨帧关联同一物体、维持稳定 id，让"这一帧的车"和"上一帧的车"是同一个。→ 4.5
- **数据关联（Data Association）**：跟踪里把新观测配到已有轨迹上的匹配问题（匈牙利算法/IoU 匹配）。→ 4.5
- **NMS（非极大值抑制 Non-Maximum Suppression）**：检测后处理，抑制同一物体的重叠冗余框，只留置信度最高的。→ 4.1
- **IoU（交并比 Intersection over Union）**：两个框重叠程度的度量，NMS 和评测都用它。→ 4.1
- **BEV（鸟瞰图 Bird's-Eye View）**：把多相机/点云特征统一投到俯视平面表示，现代感知的主流范式。→ 4.4
- **传感器融合（Sensor Fusion）**：综合多传感器信息得到比单一更可靠的估计；分前融合（原始数据级）和后融合（目标级）。→ 4.5
- **前融合 / 后融合（Early / Late Fusion）**：在原始数据层融合 vs 在各自出结果后融合，精度与工程复杂度的取舍。→ 4.5
- **置信度（Confidence）**：模型对某个检测/分类的把握程度（0~1），下游据此决定信任度。→ 1.3
- **OOD（分布外 Out-of-Distribution）**：与训练/验证分布明显不同的输入；检测器只能提供风险信号，不能保证识别所有未知。→ 4.6

## 坐标、几何与变换

- **自车坐标系（Ego / Vehicle Frame）**：以本车为原点的坐标系（常见 x 向前、y 向左），感知输出多在此系。→ 3.2
- **地图坐标系（Map / World Frame）**：全局固定坐标系，定位和规划在此系工作。→ 3.2
- **刚体变换（Rigid Body Transform）**：只含旋转和平移、不改变形状的坐标变换，坐标系转换的基础。→ 3.2
- **SE(3)（特殊欧氏群 Special Euclidean Group）**：三维刚体变换（旋转+平移）的数学群，机器人位姿的标准表示。→ 3.2
- **SO(3)（特殊正交群）**：三维旋转的群。
- **四元数（Quaternion）**：用四个数表示三维旋转，无万向锁、便于插值，比欧拉角稳。→ 3.2
- **欧拉角（Euler Angles / roll-pitch-yaw）**：用三个绕轴转角表示姿态，直观但有万向锁问题。→ 3.2
- **Frenet 坐标系（Frenet Frame）**：沿参考线定义的 (s 纵向, d 横向) 坐标，把弯曲车道"拉直"，规划的利器。→ 6.2
- **UTM（通用横轴墨卡托 Universal Transverse Mercator）**：把地球经纬度投到平面米制坐标的投影，工程里常用它避开经纬度算距离的麻烦。→ 3.2
- **位姿（Pose）**：物体的位置+姿态（朝向）合起来的六自由度状态。→ 1.3
- **点云去畸变（Deskew）**：按每个点的采样时刻补偿车辆运动，把一帧扫描对齐到统一参考时刻。→ 3.5

## 状态估计、定位与建图

- **状态估计（State Estimation）**：从带噪声的观测里推断系统真实状态（位置、速度……）的问题，定位/跟踪的数学内核。→ 5.1
- **KF（卡尔曼滤波 Kalman Filter）**：线性高斯系统下最优的递归状态估计器，"预测—更新"两步循环。→ 5.1
- **EKF（扩展卡尔曼滤波 Extended KF）**：对非线性系统做一阶线性化（求雅可比）后套用 KF，工业界最常用。→ 5.1
- **UKF（无迹卡尔曼滤波 Unscented KF）**：用一组采样点（sigma points）传播非线性，不用求雅可比，强非线性下更准。→ 5.1
- **协方差（Covariance）**：刻画估计不确定性的矩阵，卡尔曼里和状态一起被更新，是"不确定性显式建模"的载体。→ 5.1
- **粒子滤波（Particle Filter）**：用一群带权采样点近似任意分布，处理强非线性/多峰，代价是算力。→ 5.1
- **SLAM（同步定位与建图 Simultaneous Localization and Mapping）**：一边估计自身位姿一边建环境地图，鸡生蛋问题的经典解法。→ 5.3
- **NDT（正态分布变换 Normal Distributions Transform）**：把点云建成体素高斯分布再配准，激光定位常用。→ 5.3
- **ICP（迭代最近点 Iterative Closest Point）**：反复"找最近点对+求最优变换"来配准两片点云。→ 5.3
- **点云配准（Registration）**：求两片点云之间刚体变换的过程，ICP/NDT 是其代表方法。→ 5.3
- **因子图（Factor Graph）**：把状态估计表达成变量节点+约束因子的图，做全局优化，现代 SLAM 主流。→ 5.3
- **高精地图（HD Map / High-Definition Map）**：厘米级、含车道级几何与语义（车道线、限速、红绿灯）的先验地图。→ 5.3
- **航位推算（Dead Reckoning）**：仅靠运动模型（如轮速+IMU）累积推算位置，会漂移，需绝对定位纠正。→ 5.2

## 预测与规划

- **行为预测（Behavior Prediction）**：推断其他交通参与者未来的运动，输出常为多模态轨迹+概率。→ 6.1
- **多模态预测（Multimodal Prediction）**：对同一物体输出多条可能未来（如"横穿"vs"等待"）各带概率，规划须对所有高概率模态安全。→ 6.1
- **恒速模型（CV, Constant Velocity）**：假设物体保持当前速度匀速直线，最朴素也最诚实的预测基线。→ 6.1
- **行为决策（Behavior Decision）**：规划的离散层，先决定"减速让行/超车/跟随"等语义动作。→ 6.3
- **轨迹生成（Trajectory Generation）**：在决策约束下生成平滑、舒适、动力学可行的具体轨迹。→ 6.2
- **A\*（A-star）**：带启发式的图搜索最短路算法，常用于粗略路径搜索。→ 6.2
- **RRT（快速探索随机树 Rapidly-exploring Random Tree）**：在高维空间随机采样建树找可行路径，适合复杂避障。→ 6.2
- **Lattice Planner（网格/格点规划器）**：预先生成一组候选轨迹（motion primitives）再按代价选优。→ 6.2
- **Frenet 采样（Frenet Sampling Planner）**：在 Frenet 系里对横纵向撒一组候选轨迹再评估，Apollo/Autoware 主力方法。→ 6.2
- **QP（二次规划 Quadratic Programming）**：目标二次、约束线性的优化问题，轨迹/速度平滑常转化成 QP 求解。→ 6.2
- **代价函数（Cost Function）**：把安全、舒适、效率、合规量化成一个可比较的分数，规划据此选优。→ 6.2

## 控制

- **PID（比例-积分-微分控制器 Proportional-Integral-Derivative）**：最经典的反馈控制器，按误差的现在/过去/趋势三项加权输出。→ 7.2
- **积分饱和（Integral Windup）**：误差长期同号使积分项过度累积、导致大超调，需限幅或抗饱和。→ 7.2
- **LQR（线性二次调节器 Linear Quadratic Regulator）**：对线性系统、二次代价求最优反馈增益，控制界"漂亮的解析解"。→ 7.2
- **MPC（模型预测控制 Model Predictive Control）**：每步用模型预测未来一段、解一个带约束优化、只执行第一步、滚动重复；能显式处理约束。→ 7.2
- **Pure Pursuit（纯跟踪）**：横向控制的几何法，让车头对准参考线上的前视点，低速稳、实现简单。→ 7.2
- **Stanley（斯坦利控制器）**：用前轴横向误差+航向误差的横向控制法，DARPA 挑战赛成名，高速表现好。→ 7.2
- **前视距离（Lookahead Distance, Ld）**：Pure Pursuit 里向前取目标点的距离，通常随车速增大以求平顺。→ 7.2
- **自行车模型（Bicycle Model）**：把四轮车简化成前后两轮的运动学/动力学模型，控制入门与仿真的标准试验台。→ 7.1
- **运动学 vs 动力学模型（Kinematic vs Dynamic Model）**：前者只管几何关系（低速够用），后者含质量、轮胎力（高速/激烈工况必需）。→ 7.1
- **横向 / 纵向控制（Lateral / Longitudinal Control）**：分别管转向（跟线）和速度（油门刹车），常解耦处理。→ 7.2

## 中间件与通信

- **中间件（Middleware）**：连接各模块进程、负责发现/通信/序列化的基础软件层，自动驾驶的"神经系统"。→ 8.1
- **ROS 2（机器人操作系统 2 Robot Operating System 2）**：机器人领域主流开源中间件+工具生态，基于 DDS。→ 8.2
- **rclrs**：ros2-rust 社区维护的 ROS 2 Rust 客户端库，API 仍在演进，使用时应锁定版本。→ 8.2
- **节点（Node）**：ROS/中间件里一个独立的通信单元（通常一个进程），各跑各的频率。→ 8.2
- **话题（Topic）/ 发布-订阅（Pub-Sub）**：多对多的异步消息通道，发布者发、订阅者收，彼此不需知道对方。→ 8.2
- **DDS（数据分发服务 Data Distribution Service）**：ROS 2 底层的工业级发布订阅通信标准，含丰富 QoS。→ 8.3
- **QoS（服务质量 Quality of Service）**：通信策略配置，如可靠性(可靠/尽力)、历史(KEEP_LAST/ALL)、时限，直接影响系统行为。→ 8.3
- **Zenoh**：Rust 写的下一代机器人/边缘通信中间件，统一 pub-sub、查询、存储，低开销。→ 8.3
- **零拷贝（Zero-copy）**：进程间传大数据（如点云）时不复制、只传共享内存指针，省时省内存的关键优化。→ 8.3
- **CyberRT**：百度 Apollo 自研的实时通信框架，可类比但不同于 ROS 2。→ 8.1
- **序列化（Serialization）**：把内存里的结构体编码成可传输/存储的字节流（及其反向），跨进程通信必需。→ 8.4
- **IDL（接口定义语言 Interface Definition Language）**：用中立语法定义消息结构、再生成各语言代码，保证跨模块一致。→ 8.4
- **背压（Backpressure）**：消费者跟不上时限制生产或按策略丢弃，防止队列和延迟无限增长。→ 8.5
- **Freshness（数据新鲜度）**：当前时刻与数据有效采集时刻之差；过期的正确结果仍可能不安全。→ 8.5

## 仿真、测试与工程

- **仿真（Simulation）**：用软件构造虚拟世界测试算法，不用真车就能大规模试错。→ 9.1
- **CARLA**：开源的自动驾驶高保真仿真器，含渲染、物理、传感器模型，业界常用。→ 9.1
- **SIL（软件在环 Software-in-the-Loop）**：被测软件在纯仿真里闭环运行的测试方式。→ 9.2
- **HIL（硬件在环 Hardware-in-the-Loop）**：把真实控制器硬件接入仿真闭环测试，更接近上车。→ 9.3
- **数据回放（Log Replay / Rosbag）**：录制真实路测数据、离线重放来复现问题和做回归测试，数据闭环的一环。→ 9.2
- **数据闭环（Data Closed-Loop）**：路测采集→挖掘难例→标注→训练→仿真验证→再上车的持续迭代循环。→ 9.2
- **回归测试（Regression Test）**：改代码后自动重跑历史场景，确保没把原本对的改错。→ 9.2
- **WCET（最坏执行时间 Worst-Case Execution Time）**：一段代码在最坏情况下的耗时上界，实时系统排期的依据。→ 9.3
- **实时性（Real-time）**：不只是"快"，而是"能在确定的截止期(deadline)内完成"，控制/安全的硬要求。→ 9.3
- **软实时 / 硬实时（Soft / Hard Real-time）**：偶尔超时可容忍 vs 超时即失效，二者设计代价天差地别。→ 9.3
- **OTA（空中升级 Over-the-Air update）**：通过网络远程更新车上软件，量产车持续迭代的关键，也是安全攻击面。→ 9.3
- **确定性（Determinism）**：相同输入必得相同输出（含时序），是可复现测试和调试的前提。→ 9.2
- **SBOM（软件物料清单 Software Bill of Materials）**：列出制品所含组件、版本和来源，用于漏洞影响查询与供应链治理。→ 9.4

## Rust 语言

- **所有权（Ownership）**：每个值有唯一所有者、离开作用域即释放，Rust 无 GC 却内存安全的根基。→ 2.2
- **借用（Borrowing）**：不转移所有权地临时访问值，分不可变借用（多个）和可变借用（唯一）。→ 2.2
- **生命周期（Lifetime）**：编译器用来保证引用不会比它指向的数据活得更久的标注/推断机制。→ 2.2
- **trait**：Rust 的接口抽象，定义一组行为让不同类型实现，是泛型和多态的基础。→ 2.3
- **泛型（Generics）**：写一份对多种类型都成立的代码，编译期单态化、零运行时开销。→ 2.3
- **Result / Option**：Rust 用类型表达"可能失败"(Result)和"可能为空"(Option)，逼你显式处理错误，杜绝空指针。→ 2.4
- **`?` 运算符**：错误传播的语法糖，把 Result/Option 的错误自动向上返回，让主流程干净。→ 2.4
- **anyhow / thiserror**：应用层灵活报错(anyhow)与库层定义错误类型(thiserror)的常用 crate。→ 2.4
- **channel（通道）**：线程/任务间传消息的管道（mpsc 等），Rust 并发"用通信共享内存"的主力。→ 2.5
- **tokio**：Rust 最主流的异步运行时，写高并发 I/O、定时器、异步任务靠它。→ 2.5
- **async / await**：Rust 的异步语法，写起来像同步、执行时不阻塞线程。→ 2.5
- **`Arc<Mutex<T>>`**：跨线程共享可变状态的经典组合（原子引用计数+互斥锁）。→ 2.5
- **crate / workspace**：crate 是 Rust 的编译/包单元；workspace 把多个 crate 组织成一个项目共享依赖，是大项目的标配。→ 2.6 / 10.1
- **no_std**：不依赖标准库的 Rust 子集，用于嵌入式/裸机（车载 MCU、安全控制器）。→ 2.6
- **单态化（Monomorphization）**：编译器为每个具体类型生成一份泛型代码，换来零成本抽象。→ 2.3
- **零成本抽象（Zero-cost Abstraction）**：高层抽象编译后不带额外运行时开销，Rust/C++ 共同信条。→ 1.4
