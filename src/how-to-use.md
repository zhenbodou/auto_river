# 如何使用本书

## 阅读顺序

本书是**线性递进**的，强烈建议第一遍从头读到尾，尤其是：

- **第一部分**（认识智能驾驶）建立全局地图，别跳过。哪怕你已经会 Rust。
- **第二部分**（Rust 基础）如果你完全没写过 Rust，请认真做每个例子；如果你已经会 Rust，至少完成 2.5、2.7 的并发、性能与 FFI 验收。

从第三部分开始，各章相对独立，但仍按"数据→感知→定位→预测→规划→控制→系统"的真实数据流组织，顺读体验最好。

## 三种读者的路线

| 你的情况 | 建议路线 |
|---|---|
| 编程零基础 | 全书顺读，第二部分务必动手，并完成 10.4 对应的逐章验收 |
| 会别的语言、不会 Rust | 第一部分 → 第二部分（重点 2.2/2.4/2.5）→ 后续按兴趣 |
| 会 Rust、不懂智驾 | 第一部分 → 跳过第二部分 → 第三部分起逐章精读 |

## 动手，动手，还是动手

**看代码永远学不会编程。** 本书每段代码你都应该：

1. 亲手敲进去（不要复制粘贴）；
2. 编译运行，看到结果；
3. 故意改坏它，看编译器怎么骂你——这是学 Rust 最快的方式。

书里的代码块遵循以下约定：

- 能独立运行的完整示例，会给出 `cargo new` 的项目名提示。
- 片段式代码会用 `// ...` 表示省略。
- 需要额外依赖时，会明确给出 `Cargo.toml` 里要加的行。

书中的“完整”“骨架”“伪代码”含义不同：完整示例应能在声明的环境独立运行；骨架强调接口和主路径，必须由你补齐错误处理、测试和版本适配；伪代码只用于解释算法。不要把骨架直接当量产实现。

## 用证据而不是页数衡量进度

每学完一节，到 [10.4 逐章能力验收](./part10/competency.md) 完成对应交付物。每项分为能解释、可复现实验、工程负责三级。主攻方向做到 L3，相邻方向做到 L2，其余方向建立 L1 全局认知。最后用 [10.5 毕业项目](./part10/capstone.md) 做端到端评审。

## 代码约定与版本

- Rust 版本：建议使用当前 stable，并在自己的项目中提交 `rust-toolchain.toml` 与 `Cargo.lock` 固定版本。本书片段跨多个第三方生态，构建前应按章节说明建立独立示例工程。
- 遇到需要联网下载模型、数据集或搭建 ROS 2 的重型章节，会先给出"最小可跑"的替代方案，让你在一台普通笔记本上也能学。
- 第三方 crate API 会演进；以锁定版本的官方文档为准。升级依赖要单独提交，并重新运行精度、性能与回放回归，不能盲目追“最新”。

## 遇到困难怎么办

1. **编译错误**：Rust 的错误信息是全语言里最好的之一，先认真读它，它常常直接告诉你怎么改。
2. **数学卡住**：先接受结论、跑通代码，回头再补推导。工程师不需要重新发明卡尔曼滤波，但需要会用它。
3. **概念混乱**：翻到 [术语表](./part10/glossary.md)。

## 一个提醒

书里会大量出现"在真实项目里……"这样的旁注。请特别留意它们——它们是书本知识和工业现实之间的桥，也是面试官真正想听到的东西。
